Code that runs

In a programming book, the output under an example has to be what the code really prints. Foreword runs the examples and sets their real output beneath them. Give an example the output you expect, and the book itself shows ✓ or ✗.

In the book

#import "/code.typ": run

#run("hello", ```python
print("Hello, writer.")
```, expect: "Hello, writer.")

The book shows the code, then a panel with what it printed. With expect:, the panel says Output ✓ when they match. When they don’t, it’s red: Output (✗ expected “Hello, writer.”). Change the code and the panel turns amber, out of date, as you type, before anything runs. If an example fails, the book shows the error it printed.

Running them

Above each example in the editor is ▶ Run hello, with how it stands: ✓ ok, ⚠ out of date, ✗ failed, ✗ wrong output. The Code examples view lists them all by chapter, with Run all, or Run 3 not up to date. Python, JavaScript, R, Julia, Ruby, Lua, Perl and shell scripts work, with whichever you have installed.

Each example runs on its own, in the book’s folder, so it can open the book’s files (a text to analyse, say). One that runs for more than 30 seconds is stopped. Nothing runs while you type. Examples run when you click, before you export (Export PDF offers to, if any are out of date), and after the assistant changes one.

The first time, Foreword asks: “Run the code examples in Counting Words? They run on your Mac with your permissions, so they can read and change your files. Only run code you trust.” Until you say yes, nothing runs.

The output is part of the book

The output is saved in the book’s folder, with the code that produced it. So the book prints the same output anywhere, even for someone building it without Foreword, and still shows which examples are out of date.

With the assistant

The assistant writes and edits examples, but it never runs them, and never writes their output itself. After it finishes, Foreword runs any example it changed and tells you how that went: “Ran 3 changed code examples: all fine.” Or, when one fails, “1 code example failed: fib: expected "55", got "54" (chapters/02-functions.typ:41)”, with Ask the assistant to fix them.

Why

In a technical book, the output printed under an example is a claim, and it goes stale the first time you change the code and forget to paste the new output in. Readers notice. Here the output can’t drift from the code without the book showing it.

The sample Counting Words is a short book about measuring prose with Python. It has 33 examples, 30 of them checked, analysing the opening of Pride and Prejudice.

What it doesn’t do

  • Examples run with your own permissions on your Mac, not walled off, which is why it asks first.
  • Each example starts fresh, so one can’t use what another set up. No typed input, and no plots or pictures.
  • The check is an exact match on what was printed, ignoring spaces at either end.
