FeaturesKeeping your work

Every version, kept for you

Foreword saves a version of the book as you work, and before and after every change the assistant makes. Click one to see what changed, word by word. Then take out just that change, or put the whole book back. It needs no setup, and it never touches your own Git.

When versions are saved

  • When you open the book. If it changed while Foreword was closed, that version says so: “Changed outside Foreword: ch3.typ”.
  • Ten seconds after you stop saving, whether that’s ⌘S, auto save, or a change from another program.
  • Just before each turn of the assistant, so your own edits are a version of their own, and just after, if it changed anything.
  • When you name one (“Draft sent to my editor”), and when you mark an assistant task done (“Task done: …”).
  • Before and after every restore and undo, so going back can itself be undone.

A save that changes nothing doesn’t make a version. Unsaved typing isn’t in History until it’s saved, but Foreword saves your open files before every message to the assistant, and auto saves every five minutes.

The timeline

History is a view down the side, a line of versions from Now back to “Started keeping history”. Each version is a dot, coloured by who made it: grey for you, a violet ✦ for the assistant (labelled with your request), an amber diamond for a version you named, a blue ↺ for a restore. Each shows how many files and lines it changed, with a five-block bar for size.

Click a version and its files fold out beneath it, with Compare with now, Restore this version, and, for the assistant’s, Undo these changes. A What changed tab opens beside it, with ◀ Older and Newer ▶ (⌥← ⌥→) to step through versions. History of This File, from a file’s right-click menu, narrows the line to the versions that touched that file.

What changed, in words

Code tools count changed lines. In prose, a paragraph is often one line, so “+1 −1” could mean a comma or a rewritten paragraph. What changed has a Words view: the words that went are struck through, the words that came in are highlighted, with a line of context around each passage and a link to its line. Changed equations are drawn, old → new. Lines is the usual side-by-side diff.

Click a passage, or move through it with the arrow keys, and the preview scrolls to that place in the typeset pages. The diff may be from an old version, so Foreword first traces the line to where it lives in today’s text.

Undo just the assistant’s change

Say the assistant rewrote three sentences of chapter 1, and since then you’ve fixed a typo in one of them and written a new paragraph. Undo these changes on its version takes out what it did and keeps what you did since. It works like a merge: the version before the assistant, the assistant’s version, and the file as it is now, unsaved typing included. If you changed the very words it changed, that file is left alone and named, rather than guessed at. Files the assistant created are left in place, and named too.

Restore this version puts the whole book back as it was then. Files added since are left alone (Foreword never deletes them), open files with unsaved edits are skipped and named, and the book as it was a moment ago is saved first, so you can go forward again.

Where it’s kept

In an ordinary Git repository of its own, outside the book’s folder:

~/Library/Application Support/org.typststudio.app/history/<id>.git

A version is one commit of every file in the book that isn’t ignored, pictures included. Git stores a file that didn’t change only once, so a version that changes one chapter costs about one chapter. The repository runs with your own Git settings turned off (no hooks, no signing, a fixed author), so a version is never slowed down by a pre-commit hook. It’s plain Git, readable without Foreword: the help at the foot of the timeline has Copy Git command, which gives you the git log -p line for it.

Restoring never runs Git on your book folder. Old text is read out of the repository and written through the same safe write every save uses: check the file is as expected, write a temporary copy, check again, then swap it in. An open file takes the change as one undoable edit.

Why not just Git

Engineers keep every version in Git. Most writers keep chapter-3-final-v2-REAL.docx. History asks nothing of you: no commits, no messages, no branches. Even for a book that is in Git, your log is yours. A version every ten seconds and around every assistant turn would bury it, and Foreword needs to know which changes were the assistant’s, which Git alone can’t say. So History lives outside the book, and your own .git is never read or written by it.

If the book is in Git, Source Control appears as its own view: stage, commit (⌘⏎), commit and push, pull, a graph of commits with how far ahead or behind you are. It uses your own Git settings, and nothing in it discards work: there’s no reset, checkout or clean.

Your typing and the assistant’s, at once

You can keep writing while the assistant works, in the same chapter. When a file you have open changes on disk (the assistant, Git, another editor), Foreword merges the change into what you’re typing instead of asking you to choose. Your unsaved typing stays. Their change goes in around it, as one step ⌘Z takes out.

The merge goes word by word inside a line. A Typst paragraph is usually one line, and Foreword asks the assistant for one sentence per line, so you fixing one sentence while it fixes the next is no conflict at all. Only where you both changed the same words does it ask, with a card under the passage: Claude Code changed this too, its version word by word, and Keep mine, Use theirs, or Resolve with Claude Code, which sends both versions to the assistant to combine.

A save you make while the assistant works stays, even if it then writes from the copy it read before you saved. Foreword notices that its version doesn’t have your change, keeps yours, and puts it back on disk at once.

Before this, the editor showed a banner with two buttons when a file changed under you: reload from disk, which dropped your typing, or keep my version, which dropped theirs. Both threw something away. Other tools do the same, and leave you to piece the two together by hand.

Open History
The clock in the activity bar, or View ▸ History
Name a version
Name this version… at the top of the timeline, or Book ▸ Name This Version…
Auto save
Settings ▸ Editor ▸ Auto save, every 5 minutes by default (1 to 120). It doesn’t format, so nothing moves while you type.

What it doesn’t do

  • Nothing is thinned out yet: History grows with the book. A long book’s History is a few megabytes.
  • Moving or renaming the book’s folder starts a new History. The old one stays where it was.
  • You can compare a version with the one before it, or with now, but not two arbitrary versions with each other.
  • Edits you save while the assistant is mid-turn land in the assistant’s version.
  • Only files open in the editor are merged. Source Control’s pull is fast-forward only.
